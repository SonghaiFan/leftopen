🌿 为什么做这个

当我并行让多个 agent 写代码时，开发服务器和测试服务会不断启动，监听不同的端口。忙完一天，电脑里往往留下不少还开着的服务。

问题是：现有工具要么太复杂，要么只能告诉你“端口被占用”，却说不清它到底属于哪个进程、可能来自哪个项目。

所以我做了 LeftOpen。

它安静地待在 menu bar 里，帮你一眼看清正在监听的端口、对应的进程，以及可能关联的项目。确认之后，你可以关闭那些不再需要的服务。

“把那些虚掩着的门，轻轻关上。”

为什么选择 LeftOpen？

不仅是一张 lsof 列表，而是可信赖的项目归属推理与温和克制的操作体验。

🔍

基于事实的工程归属

不再显示冰冷的 node 或 python。通过解析 .git、package.json、pyproject.toml 与 macOS .app Bundle，精准还原本次监听背后的真实项目。

🛡️

温和克制，绝不盲目 SIGKILL

关闭服务前完整预览该 PID 占用的所有关联端口；关闭瞬间二次核实进程身份与启动时间；仅发送温和的 SIGTERM 信号，拒绝系统级进程与越权操作。

🌐

LAN 局域网暴露警示

自动识别监听地址属于仅限本机（127.0.0.1）还是暴露在局域网（0.0.0.0 或局域网 IP），避免开发中的接口与后台在公共 Wi-Fi 中意外走光。

⚡

极致轻量的原生 macOS 体验

基于 SwiftUI MenuBarExtra 构建，零后台服务驻留、零遥测上传、无 Electron 臃肿负担，常驻菜单栏即开即用。

设计边界与安全机制

我们对待每一次进程操作都如履薄冰。

为什么不做一键暴力 Kill？

很多后台服务可能包含未保存的数据或正在写入数据库。LeftOpen 坚持通过 SIGTERM 礼貌请求进程自行清理退出，且永远不会在后台自动升级到 SIGKILL。关闭前还会呈现其共享占用的其它端口，避免意外牵连。

它会在后台偷偷扫描或消耗 CPU 吗？

不会。LeftOpen 没有单独的守护进程（Daemon），也不启动任何网络服务。它仅在启动、面板弹出以及每 60 秒做一次瞬时读取，完全属于本地只读事实收集。

它是如何通过 Apple 官方公证的？

LeftOpen 使用 Apple 开发者身份签名，并由 Apple Notary Service 完成了官方恶意软件与安全策略机审，在 macOS Sonoma (14.0+) 上下载即可直接打开，无需对 Gatekeeper 妥协。
